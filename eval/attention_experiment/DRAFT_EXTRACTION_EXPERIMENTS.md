# DSpark Draft 关键信息提取能力实验报告

**日期**: 2026-08-31
**模型**: baseline DSpark draft(`/home/y50063564/checkpoint_best`, 5 层 GQA, 32Q/8KV/head_dim128) + verifier `/home/y50063564/Qwen3-4B`
**目标**: 在"从长上下文中提取虚构关键信息"的场景下,检验 draft 的提取能力是否对**上下文长度、关键 token 位置、语义相似干扰(distractor)、信息更新**鲁棒。

---

## 0. 方法学(重要)

- **陈述补全格式**(非 QA 格式): draft 是 next-token 预测器,面对 "Question:..." 只会续空格/问号(P=0)。改用 **"关键信息在上下文中 + 末尾补全 'The access code for Velora Station is'"** 让 draft 预测答案码。
- **虚构信息**(免先验): "the access code for Velora Station is **Alpha**"(Alpha 为单 token、在 draft 32000 词表内)。已用裸 prompt 控制实验确认 draft 对 "Velora Station 的码" **无先验**(裸 prompt P≈0)。
- **强制末尾锚点**: `select_anchors` 默认排除末尾 block_size 位,为让 draft 预测答案,强制在 query 末尾加锚点。
- **度量**: 答案槽位(末尾锚点块 j=1)每层头平均注意力,分给**关键 token 跨度**(所有子词求和)的比例;以及 P(正确码首子词)。
- **每层单独报告**(不用 5 层均值——均值掩盖"深层主导"的趋势)。
- 填充句: 程序化生成的多样无关句子(非重复循环)。

## 1. 实验1: 长度 × 关键 token 位置矩阵

**设置**: 长度 128/256/512/1024/2048 × 关键句位置 10%/25%/50%/75%/90% = 25 组合;关键句 "The access code for Velora Station is Alpha." 放入对应位置,其余用无关填充句,末尾补全 "The access code for Velora Station is"。greedy, seed=42。

### 每层关键 token 注意力(按位置平均)

| 长度 | L0 | L1 | L2 | L3 | L4 | P(Alpha) 范围 |
|---|---|---|---|---|---|---|
| 128 | 0.2% | 0.4% | 6.7% | 15.3% | **20.6%** | 0.85~0.93 |
| 256 | 0.1% | 0.2% | 4.4% | 12.4% | **17.7%** | 0.89~0.92 |
| 512 | 0.1% | 0.2% | 3.2% | 10.8% | **16.2%** | 0.91~0.93 |
| 1024 | 0.1% | 0.1% | 1.9% | 6.7% | **13.5%** | 0.90~0.93 |
| 2048 | 0.0% | 0.1% | 1.4% | 4.8% | **10.3%** | 0.85~0.92 |

代表格完整值(每格 = [L0,L1,L2,L3,L4]):

| 长度 | pos 10% | pos 50% | pos 90% |
|---|---|---|---|
| 128 | [0.4,0.4,4.8,11.4,19.3] | [0.1,0.4,7.2,17.0,21.0] | [0.2,0.4,7.9,17.3,20.5] |
| 512 | [0.1,0.1,2.7,9.1,15.6] | [0.1,0.2,3.0,12.0,15.7] | [0.1,0.2,3.9,12.1,18.4] |
| 2048 | [0.0,0.1,1.1,3.3,7.8] | [0.0,0.0,1.2,4.9,10.2] | [0.0,0.1,2.0,6.4,13.5] |

### 结论

1. **每层单调递增**: L0-1 几乎不关注关键 token(0-0.4%),L2 开始显现,L3-L4 高度集中(L4 最高 21%)—— **draft 在深层主动聚焦关键 token**。
2. **长度鲁棒**: P(Alpha) 全程 0.85~0.93(即使 2048 token 也能正确提取);关键 token 注意力占比随长度下降(L4: 128→2048 从 ~20% → ~10%),但预测不受影响。
3. **位置影响弱**: 同一长度下,关键 token 在 10% vs 90% 的注意力差异小(<5pp);越靠后(越接近补全)L2/L3 略高。

> 注: 与早期 s01(Tokyo) 实验的数值差异(21% vs 9.6%)是**样本内容差异**所致(s01 含巴黎/华盛顿语义相似句稀释注意力)。受控对比下同 pipeline 的 Alpha(13.1%) 与 Tokyo(15.5%) 注意力相近。

### 滑动窗口(sliding_window 2048 vs 4096)对提取的影响

当前 draft 的 sliding_window=2048。测试增大到 4096 后,关键 token 注意力与 P 的变化:

**长度 2048(关键句始终在窗口内)**: 2048 vs 4096 窗口**几乎无差异**(每层注意力差 <0.1pp,P 相同)——因为 2048 长度的关键句距末尾补全槽都 <2048,本就在窗口内。

**长度 4096(关键句位置 10%/25%/50%)**:

| 位置 | 窗口 2048 | 窗口 4096 |
|---|---|---|
| **10%**(span@418) | L4=0.0%, **P=0.000**(距末尾 3687>2048,完全不可见) | L4=1.2%, P=0.000(可见但提取不出) |
| **25%**(span@1032) | L4=0.0%, P=0.000(不可见) | L4=1.8%, P=0.002 |
| **50%**(span@2056) | L4=4.5%, **P=0.690**(窗口边缘,被关注) | L4=2.1%, **P=0.012**(反而更差) |

**三个发现**:
1. **sliding window 2048 是硬截断**: 距离末尾 >2048 的关键句注意力=0、P=0——draft 完全"看不见"窗口外的关键信息。
2. **加大到 4096 让远处关键句可见,但仍提取不出**: 10%/25% 位置能分到 1-2% 注意力,但 P(Alpha)≈0——**draft 无法从 4000+ token 上下文提取**,窗口不是唯一瓶颈。
3. **反直觉: pos50%(窗口边缘)小窗口反而更好**(P 0.69 vs 0.012)——**小窗口把注意力"收拢"在更少 token 上,关键句相对更突出;4096 窗口把注意力摊到整个上下文,稀释了关键句**。

**对架构创新的启示**: 2048 窗口既是**覆盖上限**又是**注意力聚焦器**。要实现长上下文提取,draft 需要"既扩大覆盖、又不摊薄注意力"的机制(如分层窗口、关键句门控、可学习位置权重)。

### DSpark 注意力分布特征(per-layer 与 block 内位置)

> 前面按"关键 token 注意力"度量,这里补充 DSpark draft 注意力的**分布形态**与**block 内位置**特征。

**per-layer 特征**(答案槽位对关键 token/BOS/query 的注意力,随 5 层变化;以带混淆的 Tokyo 样本为例,均值):

| 层段 | 关键 token | BOS | 说明 |
|---|---|---|---|
| L0-1 | 0.2~0.3% | ~25% | 浅层几乎不聚焦关键 token,注意力分散 |
| L2 | ~3% | ~34% | 开始显现 |
| L3 | ~9% | 中层 | 关键 token 进入被关注前列 |
| L4 | **~9-15%** | ~64% | 深层聚焦:BOS 一枝独秀,关键 token 成为第二高被关注 token |

→ **注意力每层单调聚焦**,深层(L3-4)是"定位关键 token"的主力;但绝对占比仍被 BOS 等结构 token 主导(见 REPORT.md 更详细分析)。

**block 内位置 j=1..7 的定位能力**(最后 anchor 的 8 个噪声位置,对关键 token Tokyo 的注意力;GQA draft,s01 Tokyo 样本):

| j | 含义 | L2 | L3 | L4 |
|---|---|---|---|---|
| 0 | 锚点复制 | 0.5% | 0.4% | 0.9% |
| **1** | **预测答案** | 3.0% | **9.4%** | **9.6%** |
| 2 | 续词 | 3.6% | 5.1% | 5.3% |
| 3 | | 2.8% | 2.5% | 3.9% |
| 4 | | 2.1% | 2.0% | 6.1% |
| 5 | | 1.5% | 3.7% | 5.2% |
| 6 | | 1.0% | 2.6% | 3.1% |
| 7 | | 0.8% | 1.6% | 3.5% |

→ **关键 token 定位在 block 的 j=1(第一个预测位置)达到峰值,随后随 j 增大单调衰减**(j=7 时只剩 0.8-3.5%)。这是合理的:预测答案本身时最依赖关键 token;预测后续续词时更多依赖 block 内已生成上下文。**若想让 draft 在 block 后半段也保持对关键信息的引用,需要在架构上补充(如让后段位置能再"回头"查询关键 token)。**

## 2. 实验2: 语义相似 distractor 递增

**设置**: 固定长度 512;关键句固定 ~50% 位置;distractor 数量 0/1/2/4/8/16/32 递增,均匀分布在关键句前后。distractor 与关键句**句型相似**("the access code for Melora Station is QX-124", "the maintenance code used by Velora Station is liyue" 等)。关键句内容不变。

| n | P(Alpha) | 关键token每层[L0..L4] | distractor平均每层[L0..L4] | 预测 |
|---|---|---|---|---|
| 0 | **0.866** | [0.1,0.2,3.2,12.7,**16.2**] | — | ' Alpha' ✓ |
| 1 | 0.867 | [0.1,0.2,2.8,11.9,**13.5**] | [0.2,0.4,3.2,5.8,**9.0**] | ' Alpha' ✓ |
| 2 | 0.909 | [0.1,0.2,4.0,11.5,**12.6**] | [0.3,0.4,2.1,3.7,**6.7**] | ' Alpha' ✓ |
| **4** | **0.039** | [0.1,0.1,2.0,7.1,**6.8**] | [0.3,0.4,1.8,3.0,**4.2**] | ' Z' ✗ |
| 8 | 0.006 | [0.0,0.1,1.5,4.8,**5.0**] | [0.2,0.3,1.3,2.0,**2.5**] | ' Z' ✗ |
| 16 | 0.003 | [0.1,0.1,1.2,4.1,**4.1**] | [0.2,0.3,0.8,1.2,**1.4**] | ' Z' ✗ |
| 32 | **0.000** | [0.0,0.1,0.5,1.5,**1.5**] | [0.2,0.2,0.5,0.7,**0.8**] | ' Z' ✗ |

> distractor 注意力 = 平均每个 distractor code(总和 ÷ 数量)。

### 结论

1. **n=1~2 个相似 distractor 不致命**(P 保持 0.87-0.91,仍预测 Alpha)。
2. **n≥4 时崩溃**: P(Alpha) 暴跌到 0.04 以下,预测错误('Z');关键 token 注意力**单调下滑**(L4: 16.2% → 1.5%)。
3. 关键 token 与 distractor 的注意力都在随 n 增加被"摊薄",但关键 token 受影响更严重(相对地位下降)。
4. **draft 对少量语义相似项相对鲁棒,但相似项一多就被淹没**——提取能力对"同类干扰密度"敏感。

## 3. 实验3: 信息更新 / 推理

**设置**: 512 token;上下文含 **旧码 → 更新 → 新码**:"the access code for Velora Station **was KeQing**. ... After the security update, the access code for Velora Station **was changed to Delta**." 分别问新码("... is")与旧码("... was")。同时检查 **target(verifier)** 是否正确。

| 问什么 | target 预测 | target 正确 | draft 预测 | draft P(期望码) |
|---|---|---|---|---|
| **新码 Delta** | ' Delta' | ✅ (P=0.80) | **' Ke'(旧码)** | **0.122**(低) |
| 旧码 KeQing | ' Ke' | ✅ (P=1.0) | ' Ke' | 0.951 ✓ |

问新码时 draft 每层注意力: 新码 Delta=[0.1,0.1,1.0,3.5,7.9], 旧码 KeQing=[0.3,0.3,1.8,6.5,8.4] —— **深层仍更关注旧码**。

### 结论

1. **draft 不具备"更新追踪"推理**: 问新码时仍预测旧码 KeQing(P(Delta) 仅 0.12),注意力也偏向旧码。
2. **target(verifier) 具备**: 正确预测新码 Delta(P=0.80)。
3. 含义: 投机解码中 draft 的能力上限受 target 限制;若 target 正确更新而 draft 未更新,acceptance 会下降(浪费算力)。

### 深入探究: 上下文长度 / 旧码单token / 新码出现次数

旧码换为**单 token Beta**(与 Delta 可比);补全 "After the security update, the access code for Velora Station is"。

| 配置 | 问 | draft 预测 | P(Delta) | P(Beta) |
|---|---|---|---|---|
| **短上下文 + 1句新码** | 新 | ' Delta' ✓ | **0.492** | 0.28 |
| 短 + 2句(不同句式) | 新 | ' Beta' ✗ | 0.122 | 0.58 |
| 短 + 4句(不同句式) | 新 | ' Beta' ✗ | 0.030 | 0.87 |
| 长512 + 1句 | 新 | ' Beta' ✗ | 0.000 | 0.90 |
| 长512 + 4句 | 新 | ' Beta' ✗ | 0.003 | 0.90 |

(问旧码时 draft 全部正确预测 Beta,P=0.93-0.94。)

- **短上下文 + 补全前缀与新码句对齐 → draft 能答对新码**(P=0.49),但脆弱。
- **加大新码"出现次数"没用**(n2/n4 反而更差)——因为这些不同句式**前缀不与补全匹配**,反而干扰。
- 长上下文一律选旧码(旧码句 "The access code for Velora Station was Beta" 前缀匹配最强)。

### 前缀匹配机制验证(根因)

补全前缀 `"After the security update, the access code for Velora Station is"`;新码句分"前缀一致"(is Delta)与"不一致"(was changed to Delta):

| 配置 | draft 预测 | P(Delta) | P(Beta) |
|---|---|---|---|
| aligned(前缀一致)×1 + 旧码句 | ' Beta' ✗ | 0.304 | 0.645 |
| misaligned(was changed)×1 + 旧码句 | ' Delta' ✓ | 0.492 | 0.28 |
| **aligned ×2 + 旧码句** | ' Delta' ✓ | **0.971** | 0.001 |
| aligned+misaligned | ' Delta' ✓ | 0.578 | 0.31 |
| misaligned+aligned | ' Delta' ✓ | 0.963 | 0.002 |

**结论**: draft 按**字面前缀/相邻词重叠**检索——补全去匹配前缀重叠最大的句子。**最可靠的杠杆是"让新码信息用与补全前缀完全一致 + 重复"的方式出现**(aligned×2 → P(Delta)=0.97)。单独 1 句前缀一致的仍压不过旧码句的竞争前缀。

**对架构的启示**: draft 缺**跨句聚合 + 语义改写**能力,只做字面前缀检索。可创新方向: 关键信息索引/去重聚合模块,或让 draft 感知"信息新旧"(更新追踪),以提升更新推理与抗干扰。

## 4. 总体结论

| 维度 | 结论 |
|---|---|
| **长度** | 提取能力鲁棒(2048 仍 P=0.90+),但注意力占比随长度下降 |
| **位置** | 影响弱(10%~90% 均可提取) |
| **每层模式** | 注意力每层单调递增,深层(L3-4)聚焦关键 token |
| **语义 distractor** | ≥4 个相似项击垮 draft,关键 token 注意力单调下滑 |
| **信息更新** | draft 不跟随更新,只做"检索"不做"推理";target 会 |

**总体**: draft 的"从上下文提取关键 token"能力在简单场景(长度/位置)下稳健,但**对语义相似干扰敏感**(≥4 个就崩),且**不具备跨句信息更新/推理能力**。这些是 draft 架构创新可以切入的薄弱点。
